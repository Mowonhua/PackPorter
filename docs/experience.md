# 经验

> 沉淀出的通用经验，与具体项目代码解耦，适用于后续任何任务，需合并同类项，并保持经验简洁明了。

## 1. 先造反馈回路，再谈修复

- 修复前先建立可自动运行、能红能绿的检查（契约检查、集成测试、可重放脚本均可）。
- 没红过的检查不算数：任何反馈回路建立后，必须先确认它真实执行过、真的能红（观察打印、退出码或断言失败），再信任它的绿。
- 静态结构检查（如 "控件是否接线"）与端到端行为断言分层布防：前者防脱钩，后者防逻辑错，后者才检验真实语义。

## 2. 警惕静默假阳性

- 测试框架报告 `0 tests / 0 passed / ok` 且退出码为 0 时，极可能一个断言都没执行——这是假绿，不是通过。
- 配置声明缺失（如测试 harness 类型未登记）不会报错，只会静默走默认行为；新写的可执行检查第一次运行时，必须核对输出是否符合预期路径。
- 反序列化缺省声明（如 `#[serde(default)]`）同样把字段名不匹配降级为静默空值，错误传播到展示层才可见；跨语言命名风格差异（驼峰/蛇形）必须显式映射（rename）。
- 多套件测试命令的汇总输出易误读（如 `cargo test` 逐套件分行报告，`0 tests` 可能只是某个空套件而非全部失败）；判定结果前先看完整统计或单跑目标套件。
- 自检型程序应在关键路径留下可观测输出（打印、日志），便于人工确认执行轨迹。

## 3. 跨语言脚本注意编码与运行时差异

- Windows 上含非 ASCII 字符的脚本，保存为 UTF-8 带 BOM，或明确指定默认 UTF-8 的运行时（PowerShell 7 而非 5.1）。
- 错误信息中出现乱码或 "字符串未终结" 类语法错误，优先怀疑编码解析问题，而不是逐行找语法。

## 4. 闭包与跨线程回调统一按值持有句柄

- 回调闭包（可能被多次触发）与后台线程闭包，统一采用 "先克隆句柄、再 move" 的模式；不要指望编译器从引用推断出 `'static` 所有权。
- 弱引用、共享槽位等 Clone 型句柄，在进入闭包/线程边界前显式克隆，可一次性规避借用逃逸类错误。
- GUI 回调在同一事件循环线程内串联执行：持锁状态下调用会再次加同一锁的辅助函数即同线程死锁（std Mutex 不可重入），不报错、只挂起。辅助函数改为接收调用方已持有的数据切片，而不是自己重新加锁。

## 5. 生成代码入口必须收敛到唯一位置

- 宏或构建脚本生成的类型按 crate 实例化：同一生成逻辑实例化两次，就产生两个同名不同源的类型，编译期才暴露且报错信息极具迷惑性。
- 生成类型的实例化点只放库入口一处，其余模块（含可执行入口、测试）统一引用库导出。

## 6. GUI 事件循环有惰性初始化时序

- 平台后端通常在首个窗口创建时才初始化；任何事件循环 API（投递任务、定时器、退出循环）都以 "已有窗口" 为前提，提前调用直接报错。
- 测试异步 UI 行为的可行模式：主线程先创建窗口 → 同步场景直接驱动 → 异步场景尾部进入事件循环，用定时器轮询完成标记后退出，循环返回后再复验最终状态。
- 事件循环线程内只做属性写与回调分发；任何可能阻塞的同步调用（如目录监控的启动握手、磁盘 IO、进程枚举）一律移入后台线程，完成后再经事件循环回写——这类调用偶尔同步等待且无超时，在 UI 线程调用会把整个窗口挂成 "未响应"。
- 定时器注册是个例外：后端初始化（首个组件创建）后、事件循环启动前即可注册，循环启动后照常触发，无需等窗口创建（实机验证：无边框镶边的延迟安装靠它完成）。

## 7. 接缝不存在时，先重构出接缝

- 当待测逻辑长在入口函数体内、测试无法触达时，先做提取式重构（逻辑移入库层、入口只留装配），让回归测试能驱动真实行为，而不是只锁编译通过。
- "正确接缝不存在" 本身就是需要记录的架构问题，修复它与修复缺陷同等重要。

## 8. 修复主线之外顺手建立的防御

- 为修复过程建立的临时检查脚本（如契约检查），若长期有效应保留入库，防止同类问题复发。
- 回归测试覆盖的链路越长，能顺带抓出的无关缺陷越多；这些意外收获应作为独立条目一并修复并注明根因。

## 9. DSL 与依赖 API 以本地源码为准，不凭记忆或搜索

- DSL 语法（如 Slint 属性可见性）想当然的写法（`public property`）直接解析失败；实际关键词集合以编译器源码为准（本地 cargo registry 中的 `object_tree.rs` 一查即中），比网上过时教程可靠。
- 标准控件库没有想当然的控件（如 std-widgets 无 `ProgressDialog`），导入前先核实导出清单。
- 依赖新 major 版本 crate 时，API 签名常与记忆不符（notify 8 需显式 `use Watcher as _`、sysinfo 0.33 刷新签名变化、zip 2 的 `SimpleFileOptions`）；直接读 `$CARGO_HOME/registry/src/` 下的源码或示例，比搜索快且版本精确。
- 在线文档被网络策略挡住时，本地 registry 源码是同一版本、零偏差的替代资料源。
- DSL 结构约束报错信息不含语义：`ListView` 只接受单个 `for` 子元素，滚动普通布局须改用内置 `Flickable`；组件属性名撞上内置/保留名（如 `row`）报 "Cannot override property"。两者均编译期暴露，但报错不指向真正原因，优先怀疑结构/命名冲突而非逐行找语法。
- `Flickable` 只管滚动、不提供排布语义：裸 `for` 子元素全部堆叠在原点；而直接放布局又会沿主轴拉伸摊满视口（内容少时整页变形）。正确组合是 Flickable 内放 `alignment: start` 的布局承载清单——既逐行排列，行数少时也不被拉伸。
- 颜色字面量是 `#RRGGBBAA`（透明度在最后），与常见的 `#AARRGGBB` 相反：写反时 alpha 静默为 0（如 `#66000000` 是全透明暗红而非 40% 黑），遮罩类效果"看不出任何变化"时先核对通道顺序。
- 语言惯用法交给 linter 把关：`/**` 块注释作模块文件头会触发 `unused_doc_comments`，文件级文档应使用 `//!`；批量修正前先按 linter 定位确认根因，避免逐条手改。

## 10. 用空集合表达"信息未知"是语义陷阱

- 判定函数面对空集合时，"确认为空"与"信息未知"是两种语义：键位淘汰判定把"新版文件缺失 → 键位族集合为空"误当"全部键位已淘汰"，静默丢弃本应迁移的数据。
- 字段/键在目标中缺失同理：目标文件只存非默认值时，某键缺失不代表该键被淘汰（如偏好键在新实例中普遍缺失）；"缺数据"应回退到保守迁移策略，而不是当作否定证据。
- 判定函数必须显式区分两态（如先判空返回"不可判定"而非"否"）；测试必须覆盖"目标整体缺失的初始化场景"，而不只是"目标存在但内容为空"。

## 11. 解析第三方生态的文件格式，先取样真实样本再定 schema

- 目录结构与顶层文件齐全不等于内部 schema 已知：PCL2 导出的版本 json 无 `minecraftVersion` 字段，MC 版本实际在 `clientVersion`；凭规范记忆写结构体，首次对接真实数据即整列报 unknown。
- 对接前先读取目标生态真实文件（或多样本）确认字段名与形态，再写解析定义；schema 类缺陷在合成测试数据上永远测不出来。

## 12. 声明式 UI 控件的隐式行为，先小步实测再依赖

- 双向绑定的选择类控件会把越界索引静默收敛回合法值（如下拉框把 -1 哨兵修正为 0）："未选择" 状态要用首行占位项表达，不能依赖非法索引经绑定回传。
- `visible: false` 只是看不见，元素仍参与布局计算并占据空间；页面级切换必须用条件实例化（`if` 元素），否则未显示页面的布局约束会挤压当前页面。
- 布局沿主轴默认 `alignment: stretch`：子元素少且无 `horizontal-stretch` 弹簧占位时会被摊满整行（如标题旁的图标被推到行尾与其他控件重叠）；需靠左/居中排布时显式声明 `alignment: start` 等。
- 这类行为编译器不报错、单元测试测不到，只有真实运行才暴露；对布局与绑定的直觉假设，先用最小窗口验证再写进主 UI。

## 13. 窗口样式位会骗人，视觉与行为才是取证对象

- winit(0.30) 在 Windows 实现无边框（Slint `no-frame`）时保留 `WS_CAPTION` 等样式位，靠 `WM_NCCALCSIZE` 抹平非客户区：用 `GetWindowLong` 查样式位会误判"未生效"，应以截图与交互行为为准。该实现换来 Aero Snap、DWM 阴影与 Win11 圆角的原生可用，属收益而非缺陷。
- 自绘标题栏的拖动在 Slint 1.17 无框架 API：用 comctl32 `SetWindowSubclass` 子类化窗口过程，`WM_NCHITTEST` 按边缘/标题栏返回 `HT*`，标题栏返回 `HTCAPTION` 交还系统移动循环，即免费获得贴边分屏与最大化后拖动还原；命中所需的 UI 几何以探针闭包在消息时刻读取。窗口类未注册 `CS_DBLCLKS`，双击最大化需自行按时间/位移检测后投递 `SC_MAXIMIZE`/`SC_RESTORE`。

## 14. 注入式 GUI 自动化必须先证明"打到的是被测窗口"

- `SetCursorPos`/`mouse_event` 注入的输入只作用于光标下的当前顶层窗口；被测窗口被其他应用遮挡时，用例会无声打到别的程序上：假阴性结论之外还干扰他人操作。
- 注入前先以 `SetWindowPos`（TOPMOST→NOTOPMOST）提升 z 序，并用 `GetForegroundWindow` 断言前台、失败即中止；再用被测窗口区域截图核对"所见即被测"。断言前置条件比断言结果更先救你。
